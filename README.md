# AI Resume Screening & Candidate Ranking System

An end-to-end machine learning project that classifies resumes by job category, ranks candidates against a job description, and checks how well a resume matches a role — similar to a real Applicant Tracking System (ATS).

Built as a learning project to practice the full ML lifecycle: data exploration, model training, hyperparameter tuning, model comparison, and cloud deployment.

**Live demo:** http://resume-screening.duckdns.org

---

## What This Project Does

This repo contains **two applications**, both built on the same trained classifier:

### 1. Dataset Candidate Ranking (`app.py`)
Paste a job description and the app:
- Predicts which job category it belongs to (e.g. HR, Finance, Engineering)
- Ranks the most relevant resumes from the dataset using TF-IDF + cosine similarity
- Shows match scores for each candidate

### 2. Resume ATS Checker (`app_ats.py`)
Upload your own resume (PDF, DOCX, or TXT) and paste a job description. The app estimates how an Applicant Tracking System might score your resume, including:
- An overall ATS score (0–100)
- A breakdown across keyword match, section completeness, job category fit, and formatting
- The specific keywords from the job description missing from your resume

## Dataset

[Resume Dataset](https://www.kaggle.com/datasets/snehaanbhawal/resume-dataset) — 2,484 resumes across 24 job categories (HR, Finance, Engineering, Sales, etc.), each with plain text and category labels.

## Methodology & Results

The core of this project is a systematic comparison of approaches, not just picking one model and stopping.

### Feature Engineering
TF-IDF vectorization (word + n-gram features) was used to convert resume text into numerical features for classification and similarity scoring.

### Model Comparison

| Model | Accuracy | Macro F1 |
|---|---|---|
| Logistic Regression (tuned) | 70.4% | 0.657 |
| Naive Bayes | 56.9% | 0.489 |
| SGD Classifier | 72.6% | 0.681 |
| LinearSVC | 75.1% | 0.715 |
| **Random Forest (winner)** | **~79%** | **0.759** |

Random Forest was selected after benchmarking five algorithms and running both `GridSearchCV` and `RandomizedSearchCV` for hyperparameter tuning (tree count, depth, TF-IDF vocabulary size, n-gram range, class balancing).

### Handling Class Imbalance
Some categories (e.g. `AUTOMOBILE`, `BPO`) had as few as 22–36 samples versus 120+ for larger categories. Using `class_weight='balanced'` meaningfully improved performance on these underrepresented classes (e.g. `AUTOMOBILE` f1-score went from 0.00 to 0.50).

### Sentence Embeddings Experiment (and why it was rejected)
As a further experiment, resumes were also classified using pretrained sentence embeddings (`all-MiniLM-L6-v2`) instead of TF-IDF. This underperformed (73% vs 79% accuracy) because the embedding model truncates input at ~256 tokens, discarding most of each resume's content — while TF-IDF captures keywords across the entire document. This is documented in `src/train_embeddings.py` and `app_embeddings.py` as a deliberate, data-driven decision rather than a discarded failure.

### Why ~79% and Not Higher
With only ~2,500 resumes spread across 24 categories, several with under 30 examples, this represents a practical ceiling for this dataset size — confirmed by exhausting tuning options (grid search, randomized search, multiple algorithms) that all converged to the same 77–79% range. Meaningfully higher accuracy would require substantially more labeled data.

```
    ├── tune_random_forest.py   # RandomizedSearchCV tuning pass on Random Forest
    ├── train_embeddings.py     # Sentence-embeddings experiment

```

## Tech Stack

- **ML:** scikit-learn (TF-IDF, Logistic Regression, Random Forest, LinearSVC), sentence-transformers
- **App:** Streamlit
- **File parsing:** pdfplumber, python-docx
- **Deployment:** AWS EC2 (Ubuntu), Nginx reverse proxy, DuckDNS

## Running Locally

### 1. Clone and set up environment
```bash
git clone https://github.com/Jaivarshinee2406/resume-screening-project.git
cd resume-screening-project/resume-screening
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # macOS/Linux
pip install -r requirements.txt
```

### 2. Train the model
Model files are excluded from version control (large binaries don't belong in git) — regenerate them with:
```bash
python src/compare_models.py
```
This trains and compares three algorithms and saves the best one to `models/`.

### 3. Run an app
```bash
streamlit run app.py          # Dataset ranking tool
# or
streamlit run app_ats.py      # ATS resume checker
```

---

## Deployment

Deployed on an AWS EC2 (t3.micro, Ubuntu) instance with:
- A static Elastic IP
- Nginx as a reverse proxy (routes port 80 → Streamlit's port 8501, so no port number is needed in the URL)
- A free custom domain via DuckDNS
